# 为指定器具制作声事件触发器

你是音视频感知原型的开发工程师。客户在真实工作台录像中指定一件器具，希望自动记录它的可听碰撞和摩擦，用于操作记录检索和事后复核。现场还会操作其他器具，摄像机会移动，目标也可能被拿走、转动或短暂遮挡。

请交付一个能接收新录像及新目标指示、自动生成事件记录和复核片段的程序。客户会在你的代码封存后提供未见录像；同一录像也可能更换指定器具。程序必须根据本次实际输入决定结果，不能依赖文件名、固定时间表或针对开发录像写死的答案。

这是基于真实厨房操作记录改编的感知开发委托，不涉及故障诊断、安全控制或烹饪评价。

## 输入与目标指示

开发输入见 `input/` 和 `INPUT-MANIFEST.json`。两段开发录像分别约64秒、30秒；封存验收另有两段约22秒、32秒的未见录像，来自不同原始记录。每段均为连续操作，包含：

- `scene.mp4`：854×480、25fps的无声画面。
- `audio.wav`：同期声音，48kHz、24-bit PCM；从公开压缩副本的AAC解码，保留副本声道，不进行分离、降噪、混音或声音替换。PCM是交付格式，不代表原始录制为无损。
- `targets/Q*/target.png`：从本段录像取得的一帧，框出客户指定的器具。
- `targets/Q*/target.json`：指示帧时间、原画面坐标中的目标框、目标点、目标ID、简短身份描述和未画框的参考帧路径。身份描述用于区分嵌套器具，例如外侧洗涤盆与里面的黑锅；不提供事件或操作时间表。标记帧不表示该时刻有事件。

每段录像有两个独立的目标查询。分别运行，不能把两个目标的事件合并。同一物体改变位置、朝向或被手遮挡后，仍保持其身份。画面中未被指定的同类器具属于干扰。

不提供事件表、逐帧目标轨迹、对象—声音对应表、转写、干净声轨、操作说明或类别示范音频。允许直接试听原始声音和查看原始画面。

素材是EPIC-KITCHENS真实记录的公开连续节选，由镜像发布者按动作区间裁切；并非完整未裁切长录像。组织者不提供原动作名称，也没有把不同动作或不同记录拼接成一段。镜像来源与处理见 `DATA-SOURCES.md`。

## 要检测的事件

只报告以下两类**实际可听**且与指定器具直接相关的事件。安静地拿起、移动或触碰不自动构成事件；其他器具的相似声音也不属于本次目标。

| 类别 | 定义 | 不应据此触发 |
|---|---|---|
| `impact` | 目标器具本体参与接触，产生可辨识的短促敲击、碰撞、落放或连续碰响。包括别的物体碰到目标、目标碰到台面。 | 仅看见接触；只有脚步、切菜或邻近器具碰响；无法确认与目标相关的金属声。 |
| `friction` | 在目标本体或内表面发生连续擦、刮、刷、滑动等接触，录音中可听到相应摩擦声。搅拌只有在确有摩擦声时才计入。 | 仅根据搅拌／擦拭动作推断有声；只听到水流、沸腾、说话、包装纸或另一物体的摩擦。 |

**物理接触可能涉及两个物体。** 若声音来自A与B的直接接触，且A或B本身都是可独立指示的器具，那么查询A与查询B均可报告此事件；不强迫猜测哪一方贡献了更多振动。只在空间上邻近、共同被手拿住或同一时刻移动，不算直接参与。目标的把手、底部和一体化结构属于目标；可拆下的勺子、盖子和旁边容器不自动继承目标身份。

两类确实同时可闻时可以重叠报告。不能把每次搅拌同时复制成两类。对仅有不可分辨颗粒感的接触，使用主导的可听类别；验收排除无法稳定定类的片段。

**时间与切分：** 所有时间相对于本段录像起点。事件起点是对应声音开始，终点是声音结束，短促自然衰减计入，不追踪听不清的尾部。同类、同目标的连续声群在明确停声达到0.4秒时拆开；不足0.4秒的间隔合为一段。不要把一串碰响拆成大量重叠预测，也不要用整分钟区间覆盖所有事件。若某类在本次目标上没有事件，输出空列表即可。

验收只计入视听证据足以确认的事件和负例。声源无法确认、严重遮挡且没有可接续身份线索、或分类争议较大的时间段不参与内容评分。不能靠推测隐藏动作获得分数。

## 程序接口

统一入口：

```text
python3 detect.py --video /input/scene.mp4 --audio /input/audio.wav --target /input/targets/Q1/target.json --output /output
```

路径、文件名、查询ID和目标框在验收中可以变化。相对路径字段以 `target.json` 所在目录解析。只依赖参数指定的媒体、目标指示，以及你声明的通用模型和依赖。

每次运行在输出目录生成：

1. `events.json`：符合 `schemas/events.schema.json` 的事件列表。至少包含 `query_id`、`duration_seconds`，以及每项的 `event_id`、`class`、`start`、`end`、`confidence`。`confidence` 为0—1，封存后的默认输出阈值固定；验收不为每条录像挑选最佳阈值。
2. `triggers.jsonl`：每个事件一行，给出同一 `event_id`、类别与起止时间，便于接入操作日志。离线处理允许完成后批量输出，不要求实时预测、连接真实通知服务或播放提示音。
3. `review/`：每个事件的原始画面加原始同期声音，默认包含事件前后各1秒上下文；允许相邻复核片段重叠。另生成一张事件缩略图。
4. `index.html`：本次查询的本地复核页面，展示指定器具、事件列表与实际复核片段；可以播放、跳转核查。页面从本地HTTP服务打开，不依赖外部CDN。

允许离线分析整段录像后输出。无需在线训练大模型；可以使用通用预训练模型、声学分析、视觉跟踪、视听推理及其组合。实现路线不计分，不按代码量、模型大小或网页装饰给分。

## 最终交付

全部保存至 `/workspace/submission/`：

- `detect.py`、`src/`、`requirements.lock`、`README.md`：源代码、准确依赖版本、启动和重运行说明。
- `models.json`：通用模型／推理服务名称、版本、来源、许可、校验值和所需环境变量名；不写入密钥。大权重可存于声明的模型目录或由固定校验值的获取脚本恢复。
- `results/`：对全部开发查询运行的上述输出。
- `CREDITS.txt`：保留输入数据署名、许可和组织者的裁切／转码说明，声明额外模型和软件来源。
- `design-notes.md`：简述如何联合使用声音和画面、如何维持目标身份、如何切分事件和已知局限。建议不超过1200中文字。

客户会把交付放到新目录运行，并更换录像与目标指示。支持通用的缓存和模型权重；缓存中不得夹带所选源视频的事件标签、答案音频、逐对象检测真值或预计算测试结果。

## 工具、资源和联网

服务器Docker提供Python、FFmpeg、NumPy、SciPy、SoundFile、Pillow、PyTorch与OpenCV；固定环境清单见 `ENVIRONMENT.json`。可用8 CPU、16GiB内存、30GiB工作空间，不承诺GPU。

开发有效时间7200秒，最多140次成功候选模型调用，累计输出131072 tokens，单次最多8192 tokens。公开网络工具上限80次请求、下载总量2GiB；失败请求和重定向计入。组织者预置输入不占下载额度。

允许联网获取通用模型、依赖和技术资料。不得获取本题源视频对应的EPIC-SOUNDS／动作／对象轨迹标注、隐藏验收资料或他人本题答案。来源与许可证已由组织者提供，无需检索原视频寻找答案。

最终推理可使用本地模型，或已申报且经组织者在测试前确认可用的通用远程推理服务。后者由同一计数网关提供开发与封存验收两阶段访问，密钥由组织者注入；验收每查询另给最多40次推理请求，不挤占开发额度。远程服务只接收本次输入和任务定义，不能读取答案。正式测试前需冻结所用服务、版本和预算；服务不可用时先修复环境，不据此给内容低分。

封存验收每条查询允许最多1200秒处理，8 CPU、16GiB；超时先检查是否环境或依赖失败，不能将组织者工具故障记为模型识别失败。不评分实时延迟。

## 评分与高分标准

100分均评价自动事件判断：事件识别与目标归属70分，困难负例控制20分，边界质量10分。可运行程序、真实输入依赖、可播放复核片段和完整交付作门槛，没有基础工程分。详细匹配规则、公式和满分条件见 `SCORING.zh-CN.md`。

高分结果应同时做到：目标有声时不漏报，其他器具有相似声时不误报，目标安静动作不触发，目标转动／移动后身份仍连续；起止贴合声音，换录像或换目标后仍成立。静音式空输出、把全场声音都报给目标、长区间覆盖一切和写死开发答案均不能取得高分。

本题不要求声音生成、音轨分离、拟音、重建原声或制作教学材料。
