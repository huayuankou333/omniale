# 画面指定人物的真实重叠原声抢救

你是纪录片后期的对白编辑师。团队只有多人现场谈话的同期混合录音，需要把导演在画面中指定的人物抢救成可以继续剪辑的独立原声轨。现场有餐厅环境声、打断、抢话及共同发笑。不能把其他人的话当成目标人物，也不能靠删掉重叠段交一条“很干净但缺话”的轨道。

本题使用公开研究数据中的真实多人录制，不是组织者把几条干净人声人工相加。应用场景为模拟后期委托，原始拍摄本身是研究实验。

## 输入

`input/A/`、`input/B/`、`input/C/` 是三条彼此独立的连续记录，各约一分钟。每条分别完成，不要拼成一条谈话，也不要假设三条记录指定同一个人。实际帧数、时长和校验值见 `INPUT-MANIFEST.json`。

每条包含：

- `scene.mp4`：连续现场画面，20 fps，无内嵌声音。已裁去数据集原视频旁边的人物编号肖像栏，实际拍摄区域保留。没有逐帧目标框。
- `array.wav`：与画面同起点的 48 kHz、六声道原始阵列混合录音，声道顺序保留。
- `monitor.wav`：`array.wav` 第五声道的逐样本复制，用于原录音对照及残余轨重组。不是额外声源，也不是干净目标声样。
- `target.png`：同一记录的一帧全景图，以框和箭头指定需要保留的人物。图上给出帧时间；框只负责指定身份，不表示该时刻一定正在说话。

`calibration/` 提供通用阵列响应和音画空间标定，`CALIBRATION.zh-CN.md` 解释声道及裁切坐标。它们不提供人物声纹、发言区间或轨迹。不给转写、干净登记声样、逐句时间表、独立麦克风轨或整理好的说话人信息。

## 要完成的工作

先结合画面和混合声音判断“指定的这个人”对应哪个声源，随后跟踪到整条记录，包括转头、短暂遮挡、没有面对相机和与他人同时发声的时候。不能把嘴部活动门控当作完整分离：两人同时张嘴时，仍需保住指定人物的原声并压低另一人。

1. 保留目标的原话、原始声线、语气、停顿，以及可辨认的笑声、吸气和弱辅音。目标的短应答与被打断的半句话也属于要保留的内容。
2. 在真实重叠段中同时实现目标保留和其他人声抑制。目标未发声时，目标轨应安静；不要把邻座的词句、笑声和环境中的人声填进去。
3. 输出连续、自然、可剪辑的人声。允许合理降噪、去混响、分离和局部修补；避免水声、金属音、抽吸、断字、爆音或跨时刻换人。轻微剩余环境底噪可以接受，不能以牺牲原话换取绝对静音。
4. 时间线保持原长、原速、原位置。不要跳切、挪动一句话补到另一个位置，或通过缩短交付隐藏难段。

不要求恢复近讲麦克风的声音、逐样本反演唯一声学真值、猜出原录音中无法可靠听辨的字词，或保留与人声无关的现场音效。等效的自然声学结果均可满分，轻微空间色彩差异不扣分。验收只对可由同期记录及隐藏参考确认的目标事件计分。

## 允许使用的工具与素材

可以编程、使用预训练分离/增强模型、合理联网获取通用模型和依赖，并在 REAPER 中整理和试听。可以先盲分离再用画面绑定身份，也可以直接进行视听分离。方法本身不计分。

必须保留本次输入中的原始表演。不能用 TTS、声音克隆、重新配音、音素拼接生成新表演，也不能用另一次发言替换当前发言。不能下载或使用所选记录对应的独立近讲轨、转写、人物活动标签、轨迹、隐藏验收包或其他答案资料；这属于测试参考泄漏。通用模型及通用训练数据不受此限制，须申报名称、版本和来源。若意外接触到答案资料，写入处理记录，停止将其用于声音制作。

## 交付

保存至 `/workspace/submission/`，路径均为相对路径，换目录后可以打开：

- `A/target.wav`、`B/target.wav`、`C/target.wav`：各自连续的目标原声，48 kHz、单声道、32-bit float WAV，与对应 `monitor.wav` 等长。保持与原录音相容的电平，不能整体变调或变速。
- 各目录内的 `residual.wav`：同规格，在数值上满足 `target + residual = monitor`。它用于让接手者检查被移除的内容，不作为单独的额外得分项。允许目标轨与残余轨存在处理所需的反相信号。
- 各目录内的 `review.mp4`：原始画面加该条 `target.wav`，原画面顺序、20 fps、同起点、同长度。音频可用 AAC；评分读取无损 WAV。
- `session.rpp` 和 `media/`：真实可打开的 REAPER 原生工程，三条记录分开放置在互不重叠的时间区段并设区域。每条有原混合监听、目标、残余和画面轨；默认只播放目标轨，原混合/残余可单独切换。依赖齐全，不得把只有最终视频的空工程当作交付。算法可以离线处理，保留最终分离 stems 及对应生成脚本/参数即可，不强制某款插件。
- `source/`：本次处理脚本、参数与必要的小型配置；外部大模型权重可用固定版本与 SHA256 的下载说明代替，不要重复打包缓存。
- `edit-notes.md`：说明每条目标如何从画面绑定到声音、主要处理方法、仍有缺陷的位置，以及重运行命令。建议不超过 1,200 中文字，不能用说明代替声音。
- `asset-use.json`、`CREDITS.txt`：工具/模型版本、外部来源、许可、处理记录和最终文件 SHA256；保留 EasyCom 署名与 CC BY-NC 4.0 声明。

工程完整性只作门槛，没有基础工程分。提供 `tools/check_submission.py` 供你检查 WAV、长度、残余重组和相对路径；它不能代替 REAPER 实际打开、人工听审和内容评分。

## 资源与预算

服务器 Docker 提供 8 CPU、16 GiB 内存、30 GiB 工作空间，使用 CPU 也可以运行；不承诺 GPU。预装 Python、PyTorch、NumPy、SciPy、SoundFile、h5py、FFmpeg、REAPER 与 Xvfb。通用模型可按预算下载，不要求申请受限权重、购买素材或使用付费生成服务。

有效工作时间 7,200 秒，最多 140 次成功模型调用，总输出 131,072 tokens，单次最多 8,192 tokens。外部 HTTP 请求最多 80 次、总下载 2 GiB；搜索、下载和重定向各跳均计数，失败请求也计数。由记录工具统一执行，不绕过计数；安装与模型获取耗时计入工作时间。测试前必须确认这些联网工具实际可用，或预先缓存声明过的通用模型，否则不能把环境失败记成内容失败。

## 评分

100 分均评价声音：重叠抢救 60，其他目标发声保留 20，目标停声时的干扰抑制 10，连续自然性与同步 10。每个正例单元同时考查保留、抑制与保真，以三项最低档计分，不能用一个方面抵销另一个方面。后两项随目标保留覆盖率缩放，静音不因“没有干扰”拿分。

详细公式、0—4 锚点和高分标准见 `SCORING.zh-CN.md`。未处理的混合录音至多只能得到少量自然性分；删掉全部重叠发声会失去主要内容分。分离方法不同或合理的空间音色差异不扣分。
