# 3A · 决策演变与争议保留：长会议精编

你是一名会议纪录片剪辑师。请在本地 **DaVinci Resolve** 中，把随附 AMI ES2002d 的完整多机位会议，剪成供缺席项目负责人观看的 **5–6 分钟中文信息简报**。保留英文原声，用准确的中文关键字幕、人物署名和简短图卡帮助理解。可以按主题重组，但要让观众知道哪些是原始计划、临时建议、被否决的备选、最终结论，以及哪些意见只得到部分回应。

这是研究项目真实录制的情境设计会议，议题是遥控器的最终设计和项目复盘。不要把它包装成真实企业发布会、产品已量产或实测性能报告。

## 需要回答的编辑问题

每一组都是成片需要覆盖的需求。允许一句话/一个片段同时回答多个问题，不需要为每项制作单独章节。

1. **P1 方案演变**：开场回顾、本次原型和最后配置有何不同？说明显示反馈、芯片和供电方案的变化，以及删改原因和替代办法。不要把较晚出现的提议自动视为最终决定。
2. **P2 成本与取舍**：交代原始报价、需要节省的数额及当场纠错、最终是否在预算内；区分外形备选与实际采纳方案、按钮数量与计价估算、键盘颜色与整体配色、中途余额与最终成本。不给未经证实的精确报价。
3. **P3 原型与使用性**：解释实体原型的扁平外观与预期厚度的关系、讨论中的最终厚度估计，以及按键布局创新与熟悉性之间的取舍。
4. **P4 评价结果与保留意见**：正确解释评分量表方向及纠错，交代风格、创新和软弹触感三项评价。让观众理解数值与具体取舍之间的关系，保留有关配色受欢迎程度的疑虑；不能把高低方向读反。
5. **P5 未通过的后续构想**：交代产品评价后继续提出的形态/色系建议处于什么状态，避免把建议升级成已批准事项。
6. **P6 创意限制与澄清**：交代对创造空间的词义误会及澄清、至少一个具体约束冲突、佩戴设备与交流困难的观点，以及对团队氛围的随后纠正。
7. **P7 不同立场**：保留“领导/控制”与“结构化流程”的不同表述及理由，保留批评中的限定和随后的缓和；说明会外交流限制、团队合作评价中的让步，以及会议限时的收益和例外。不得把这些剪成人身指责、全员一致否定或持续敌对。
8. **P8 晚出现的信息**：完整检查会议结尾，保留收尾后仍出现的实体原型/触觉与创意方法反思，不要在第一次宣布结束处就停止搜索。
9. **P9 跨模态证据**：人物、原声与署名对应；追踪离开座位后的评价者；保留真实白板活动；给原型、量产设想和回顾画面恰当标签。厚度手势、预算纠错、领导观点交接、设备批评和后段限时观点应有可核对的同期原声/画面。保护有意义的抢话和否定词，不制造虚假的当场反应。原型、白板评价、领导争议三段至少各留一个可复核音画时间关系的镜头。
10. **P10 专业交付**：交付可编辑的 Resolve 工程、从该时间线导出的成片、混音和来源映射，具体要求见下文。

## 素材和教程

- `media/video/*.avi`：五路上游原始视频，未经裁切或内容修改。
- `media/resolve/*.mp4`：相同五路视频的 H.264 兼容副本，保留原像素尺寸、帧率与时间原点；可优先用于 Resolve。不是生成或修复过的画面。
- `media/audio/*.wav`：四路耳麦和官方混合轨。使用混合轨是允许的；只有需要保护重叠发言、处理电平或局部噪声时才需切换/组合单轨，不按加工复杂度评分。
- `MEDIA_MANIFEST.json`：每个输入的时长、格式、校验值和转换关系。全部时间指媒体从 0 秒开始的源时间，不是墙上时钟。
- `tutorial/`：Blackmagic Design 官方 Fairlight 音轨分层教程。先查看其中与任务有关的部分，再在 `README.md` 中记录一处适用方法及其落实位置，或说明为何某方法不适用。教程不是这场会议的答案，也不把时间戳引用等同于已经证明学会迁移。

原片为低清真实记录。不要依赖看不清的白板微小字符来编造精确数字，可依据原声制作清晰的编辑注释；不能把编辑注释伪装成原始板书。角色可用稳定代号（如发言人 1–4），不要求识别私人真实姓名；若使用职能角色称呼，必须有依据。

## 允许的工作方式

必须实际使用本地 Resolve 创建/编辑和导出时间线。允许 GUI、Resolve 原生脚本，以及 FFmpeg、ASR、Python 等辅助检索、分析、格式转换。不得仅将外部完成的整条成片导入 Resolve 来伪装原生剪辑。不得使用生成的人声、对话补写、合成会议镜头、替换面孔或生成超分辨率“恢复”的细节。

正式运行的可用输入仅为本 `public/` 文件夹；不得读取出题者 `private/`、历史模型结果，或联网寻找本会议的官方转写、摘要、决策答案。允许使用软件官方文档。中文翻译、标题、必要图卡是编辑表达，不属于额外会议素材；允许制作，但必须忠实于原声和真实画面。

可重排、使用 J/L cut、同期多画面、字幕压缩和合理裁切；不按剪切数量或插件数量加分。不得改变对白播放速度来塞入更多内容。每个主张必须在成片中可理解，附件说明不能替代成片遗漏的信息。重叠发言可分开呈现，只要不改变意思、说话者与先后关系。

## 交付规格

在单独输出目录中提交：

- `final.mp4`：300–360 秒（含片头片尾），25 fps，1280×720，H.264，AAC 48 kHz。源画面保持原比例，允许留边或多画面；不因原片低清扣画质分。
- `project.drp`：可重新链接题包素材的 Resolve 原生工程。画面片段、音轨与字幕/图卡保持可编辑，不是单条烘焙整片。
- `mix.wav`：与成片等长的 48 kHz PCM 混音。目标 -18 LUFS±2，真峰值≤-1 dBTP。无需为了达标过度降噪或损伤字词。
- `edit_map.json`：按 `schemas/edit_map.schema.json` 记录音频、视频及关键图卡的源/输出时间；J/L cut 的音画应分别记录，非同期插画写明用途。
- `claims.json`：按 `schemas/claims.schema.json` 列出成片主张、提案/决定/保留意见状态、源证据和输出时间。不要求与评委内部条目编号一致。
- `speaker_map.json`：按 `schemas/speaker_map.schema.json` 说明所用稳定身份标签、音轨和实际机位/离座情况，以及用于确认身份的时间窗口。
- `README.md`：复现工程与重链接方法、采用的 Resolve 版本、主要编辑取舍、教程方法应用、源素材本身的局限。不提交 API 密钥。

模板放在 `templates/`，都是空白结构，必须填写。来源映射中的 `source` 路径相对于本 `public/` 目录。

原型、白板评价、领导争议三段的同期画面，相对所用源音画不得新增超过 2 帧（80 ms）的时间映射偏差。若原素材本身存在误差，在 README 中记录并提供证据；不得把上游缺陷算作人为失误。正式核查以实际导出和工程为准，不能只靠自报时间映射。

## 评分方式

内容与语义忠实度 60 分，跨模态证据 30 分，工程与交付 10 分。评委按 0/半分/满分核对各项；不同合理剪辑都可以得分，不要求复刻唯一参考片。关键错误会单独报告，例如把建议当决定、反转量表、错配人物或删掉反驳里的否定词。避免某个事件不展示，不会得到该事件的“无错误分”。
