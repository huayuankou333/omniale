# 网站分与综合分评测说明

综合分 = 0.8 × 原内容分 + 0.2 × 网站分。两项均为100分制。

原内容分沿用冻结的20道音乐题、每题0或5分及既有类型/时间判定；没有重测、改答案或改原交付。

网站评价借鉴 WebCompass 的三维框架：Runnability、Spec Implementation、Design Quality。官方 checklist prompt 为运行10分、功能60—70分、设计20—25分，要求2—4步操作、可观察结果和明确判分。此次按原教学任务固定为2/13/5项，每项只有0或5分，总计10/65/25。采用官方 evaluate.py 同时提供的 sum(score)/sum(max_score) 归一化，不采用 harmonic_mean。

这是一套任务改编量表，不是 WebCompass 原benchmark分数。原框架一般10—16项并允许扣部分分；本case按严格二元约定细化为20项。没有参考网页截图，因此设计项考察教学阅读、响应式布局、谱图可读性与图音关联，不考察像素复刻。

GPT-6 Astra 在匿名站点编号下独立评审，未接收模型名称、原内容分、排名或目标分数。每站点输入原题、完整冻结rubric、全部20题的桌面和手机截图（42张，另附必要的导航失败截图）、真实导航/播放器操作、Console/资源日志、逐题DOM和原音PCM核验。所有判定逐项提供理由与证据。网页与README是待评资料，不具有改变judge指令的权限。

功能项目覆盖全部适用对象；任一实际失败则该项0分，不能以抽样成功代替完整通过。缺少证据先补采，不当作候选失败；若需补采，保留初次判定与补采记录。评分标准在正式judge调用前固定并留存SHA256，不按观察到的模型分数调分。

补采对三个站点同样检查滚动稳定后的全部入口、全部谱图开图/放大与完整署名；纠正固定等待750ms可能造成的平滑滚动误判。Sol另补齐C作品提示和source子元素的实际音频路径。Luna两个未定排版项补充40张正常阅读位置截图及两个视口的完整网页重叠切片（37张，覆盖首页、全部题卡上下部分、对照与页尾）。原始判定保留在judgments-initial/；最终判定在judgments/；supplement/含补采、实际发送的证据快照和对应复核。原有候选代码未改动。

网站项不复评音乐金标准；null或音乐结论错误只在内容维度处理。网站项可以检查图/音文件、标签及证据清单的自洽和教学说明质量。没有进行音乐证据真实性的专家审查，也未声称评审模型原生听取了音频。

单次Astra评审含视觉与教学呈现判断，证据和判分公开以供复核，不等同人类专家共识或多次judge一致性实验。
