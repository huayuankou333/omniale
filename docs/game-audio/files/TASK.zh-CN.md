# Relay Workshop：为检修小游戏完成交互音频

你是负责接入试玩版的技术音频设计师。团队已经完成一个可玩的设备检修关卡，现在需要你交付声音设计、资产制作和实时接入。附件中的有声试玩是行为和风格参考；当前工程的声音入口为空，也没有可直接使用的音效资产包。

请根据试玩中的音画关系，为这个小游戏制作一套完整、可交互的声音。声音应帮助玩家理解设备、工具和操作结果，并能在不同操作顺序下持续工作。这是组织者自建的灰盒关卡与录制素材，不是真实商业项目遗失的工程。

## 输入与任务边界

- `project/`：Godot 4.5.1 原生工程，已有移动、两台设备、检修工具、隔离门、通关逻辑与画面。`audio/audio_system.gd` 留空。不要重做玩法。
- `input/recordings/`：四段连续有声试玩，总计约 4 分钟。它们包含独立操作和同时操作、短操作和长操作、成功与失败、设备运转与隔离门变化。无逐事件标注、按键日志、声轨分轨或声音用途清单。
- `input/development-replay.json`：开发用操作回放，没有对应的标准声音。
- `INTERFACE.zh-CN.md`、`tools/render.py`：玩法接口和真实引擎录制工具。
- `SCORING.zh-CN.md`：公开的声音验收标准。

没有匿名声音池或预制工程音效。你可以用预装的 Python/FFmpeg/Godot 制音、分层和加工，也可以检索允许再分发的开放音效。无需购买素材、申请账号、调用付费生成服务或安装专有中间件。是否联网和使用多少文件本身不加分。

## 需要完成什么

先观察和试听，判断连续混音中的声音属于哪个对象、动作和状态，哪些声音持续、变化、被打断或保留尾音；再制作可用的声音资产并接入工程。参考录像的播放时间不能成为控制逻辑。

1. 玩家和自主单元的接触反馈应独立，体现实际接地、表面和动作强度；重复操作保有同类质感，又不出现刺耳的短样本机械复读。
2. 工具、两台设备和隔离门的发声行为应遵循参考中可辨认的状态关系。特别注意进入与持续、有效结果与无效结果、中断与再次操作，以及设备各自持续运转时的相互独立性。
3. 连续参数的听觉变化应随实时状态发生。不要以固定长度文件代替任意时长的持续状态，也不要把画面中的多个不同对象合并成一条通用持续声。
4. 保持参考中可听的对象区别、主要声层及信息层级。声源远近、左右位置和隔离门对相关设备的影响，应与当前场景关系一致。暂停后按下述验收约定处理。
5. 在单独操作、同时操作和操作重排时，关键反馈保持可辨；声音不因重复触发不断累积。音频完全来自运行中的原生工程。

**声音身份允许重新设计。** 不要求恢复参考的原文件、精确频率、滤波器系数、每个谐波或逐样本波形。允许使用不同素材，做出符合相同对象质感、行为、层次和相对关系的声音。例如参考中的两种机械运转必须仍能区分，但不要求复制某个电机录音的频谱指纹。满分标准是下文和评分文件中的可观察条件，而不是组织者私有源码。

参考录像可以作为制作素材进行抽取、分离和再加工，须记录来源；不禁止合理的素材复用。整段参考混音按录像时间播放、携带其他对象声音的混合片段导致假事件，不能算作完成交互系统。

## 明确的验收约定

- 验收只重组已展示的动作、状态和参数范围，不新增从未展示的机制。
- 离散动作声以可见接触或状态边沿为基准，主要起音允许约 ±2 帧（30 fps，67 ms）；持续主体在退出后 100 ms 内停止或进入自然退场，普通自然尾音可延续至 500 ms。设备转速本身仍在衰减时，运转声应继续跟随转速，不按开关按下时硬切。
- 连续变化评价方向、阶段、可辨的范围及稳定性。不同的等效映射曲线均可满分。
- 验收的同源近/远对照会保持操作与设备状态相同。远处声音应可辨地减弱；关闭隔离门对其后的设备产生减弱和变闷，门外的设备不随之改变。按评分文件中成对比较的宽容差验收，不要求声学仿真的唯一解。
- 暂停：150 ms 内让可听主体进入静音，恢复后 150 ms 内回到暂停前的连续状态，不重新播放已发生的启动、成功或失败提示。暂停不应推进声音的玩法阶段。此项是明确的产品约定，不能只凭未示范规则隐藏扣分。
- 无文字解说、背景音乐或对白需求。不要用音乐掩盖缺失反馈，也不需要扩充画面、关卡或玩法。

## 工具、预算与资源

制作及验收在服务器 Docker 中进行，4 CPU、8 GB，固定 Godot 4.5.1，预装 Python、NumPy、SciPy、SoundFile、FFmpeg 和 Xvfb。制音和处理过程均可在该环境完成。声音文件和原生配置必须可编辑，不要求额外跨软件流程。

有效工作时间 7,200 秒，最多 140 次成功模型调用，总输出 131,072 tokens，单次最多 8,192 tokens。若提供联网工具，最多 40 次外部 HTTP 请求、总下载 200 MiB；搜索、网页、下载和重定向各跳均计入，失败请求也计数。缓存重复读取不重复计数。不提供联网工具时，预装的程序制音路径仍足以完成题目。所有外部访问由记录工具完成，不绕过计数。临时凭据与组织者私有目录不对解题容器开放。

## 交付

保存至 `/workspace/submission/`：

- `project/`：完整原生工程，声音脚本、资产、资源、总线和相对路径依赖齐全。固定玩法文件不得改动，声音部分可以自由组织。
- `preview/development.mp4` 与同次运行的 `development.wav`：用提供的回放和真实引擎录制，48 kHz 立体声；不能后期替换声音。
- `sound-design.md`：关键音画判断、参考录像位置、制作与接入方法，建议不超过 1,200 中文字。
- `asset-use.json`：实际使用资产的路径、来源、许可、处理记录；程序制音要指向生成脚本和参数。给出文件 SHA256。
- `CREDITS.txt`：必要署名与许可。自制素材可以明确标为原创。
- `source/`：本次程序制音、离线加工所用脚本和可编辑参数（使用这类流程时交付）。

不交 Godot 缓存、大量中间文件和外部下载缓存。素材获取、工程打开和文档完整只作门槛，不提供声音内容分。

## 评分

100 分均评价实际声音：音画关系和信息反馈 30，声音设计与资产质量 30，交互过渡和空间行为 25，混音与持续可用性 15。详细计算与满分条件见评分文件。原始静音工程为 0 分。

任何听觉上等效且满足公开条件的实现都可以得到 100 分。不会因为使用另一种合成方法、没有取回原音效、没有某款插件，或工程代码不同而扣分。满分不要求复原无法观察的私有实现。
