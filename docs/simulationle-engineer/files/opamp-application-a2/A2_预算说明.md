**A2 当前测试预算（2026 年 11 月 14 日）**

A2 沿用 A1 v2 的模型开发预算，暂不通过压缩预算制造失败。正式模型为 `gpt-6.1-sol`，每个冻结版本先运行一次独立试验。

| 资源 | 每次 Sol 试验上限 | 计数口径 |
|---|---:|---|
| 推理强度 | medium | 显式发送给 API |
| 模型回复 | 48 次 | 成功返回的模型响应；API 失败与重试另记 |
| 工具调用 | 120 次 | terminal、read_image、finish 合计 |
| 原生开发仿真 | 160 次 | 一次 ngspice 批处理调用算一次；批量脚本逐次扣减；同一批处理可包含同一电路的多个分析 |
| 累计输入 | 未单独设置 token 上限 | 历次请求重复携带的上下文也产生报告输入量；不能把输出上限当作总 token 或金额上限 |
| 累计输出 | 131,072 tokens | API usage 的 output_tokens，包含其报告的推理 token；不是上下文窗口大小 |
| 单次回复输出 | 32,768 tokens | 同时受剩余累计输出额度限制 |
| 开发墙钟时间 | 7,200 秒（2 小时） | 包含 API 等待；主循环在调用边界检查，进行中的调用可能使退出时间略超过上限 |
| 计算资源 | 每容器 2 CPU、2 GiB 内存 | A2 通过 ngspice 的 num_threads 显式固定为 1；仅设置环境变量不足以限制本镜像 |
| 单次原生仿真超时 | 120 秒 | 超时仍保留调用与日志 |
| 单次终端命令超时 | 180 秒 | 不等于每次 ngspice 的超时 |
| 候选电路 | 无“三版电路”限制 | 网关内部防护值为 161；160 次开发仿真加最后提交，不额外限制为三个候选 |

上述是并行生效的多重上限，先到达的上限会限制后续工作，不是保证可用足 160 次仿真。最终提交是模型最后留在磁盘上的电路；不从历史候选中替它挑选最优解。API 并发限流等重试保留同一任务上下文与已用预算，不当成新的独立试验。

参考解设计、负对照、数值收敛复核属于造题校准，不占用 Sol 的 160 次开发仿真。校准目前没有单独配置硬次数上限，实际开销保留在服务器 validation 目录并在最终报告中统计。冻结后的独立最终验收也单独计数，不把验收结果返回模型继续修改同次提交。

目前未设置整个项目的金额上限，也没有可核实的账户剩余额度或本次渠道单价，因此不能把 token 上限换算为一个可信的金额承诺。API usage 与失败重试会保留供核算。

A1 v2 的实际使用为 19 次成功回复、19 次工具调用、160 次开发仿真、6,142 个报告的输出 tokens、1,375.626 秒开发墙钟时间；有 3 个功能候选和 1 个核心消融诊断网表。独立验收另运行 150 次。A1 v2 的原文件和结果已保留，其满分结果不满足本轮以 Sol 未满分为必要条件的入选标准。

A2 的入选还要求：参考解通过原题与新增要求；朴素迁移或直接复用原解的负对照出现预期电气失效；模型运行与最终验收有效。基础设施故障或不可解规格不能作为题目有难度的证据。具体 A2 实测消耗以最终报告为准。
