## 原题 / GPT-6 Luna / 2026-11-08 替代轮次

开发在 759.65 s 时正常提前结束。轨迹最后有 `turn.completed`，模型明确陈述短测尚未清出零件，并提交了策略。与此前因接口并发上限异常退出的轮次分别保留。

冻结策略的 SHA-256 为 `70775dab8229b4974f31312047ae901d23e2483e96b66c10aecf3671169162cd`。

已复核的接口缺陷：策略通过 `mj_name2id(..., "grip")` 查找控制点，实际模型中的名称是 `arm_grip`，查找返回 `-1`。代码没有检查返回值，位置数组用 `[-1]` 取到 `arm_ft`，该点距磁铁接触面 `arm_grip` 为 0.197 m。检查使用同一原生镜像构建的静态工作单元，原始观测保存在 `luna-original-site.json`，复核入口为 `../diagnose_luna_site.py`。

进一步复核：该原生 MuJoCo 版本对 `mj_jacSite(..., -1)` 给出零位置/旋转 Jacobian；对有效的 `arm_grip`，位置 Jacobian 范数约为 1.0211。因此本提交的 `J.T @ solve(...)` 更新项为零，IK 不能按目标位置生成关节位移。首个隐藏回合的 0、30、60、119 秒附近采样帧也始终接近初始姿态，四帧图保存在 `frames/luna-original-ep0.png`。这项诊断解释了策略无法正常产生搬运动作的机制。

策略代码还显示：IK 只约束位置，没有末端朝向约束；状态转移主要检查关节是否接近目标，没有使用力觉或视觉确认实际接触与负载，也没有抓取失败后的明确恢复分支。这些是代码层面的能力缺口。其各自对最终分数的贡献需要额外受控消融，当前没有量化。

正式验收已完成：八回合均为 0 分，合计清出 0/112 件；0 掉落、0 损伤、0 撞箱、0 策略运行故障，四个 gate 全通过。这里的 gate 只检查加载、接口、稳定性与确定性，不保证任务完成。该提交的低分来自没有获得任务收益，不是被安全处罚或 gate 上限扣至零。

八回合验收墙钟合计 9529.77 s（158.83 min），其中策略等待 469.35 s，harness 9060.41 s。CPU 验收开销明显高于策略计算，且不计入开发预算。原提交保持冻结，没有替模型修复后再计分。现有证据支持控制点错误的机制解释；未做修复消融，不能据此量化修复后会获得多少分。

代码检查确认：使用有效 `arm_grip`，RGB-D 筛选料箱中暴露表面并利用局部几何偏移抓取点；约束末端接近方向的 IK、平滑关节插值及重力补偿；提升后等待力觉稳定，根据扣除工具质量后的负载质量匹配三类零件；过大负载执行倾斜放回再抓；料箱无候选时利用腕部相机搜索工位区域的残留零件进行恢复。代码未读取实时类别/物体位姿、隐藏种子或 harness。它利用题面中长度与质量成比例的关系进行主动称重分类，符合当前传感器和规则。

## 本轮对 case 难度的观察

原题 Sol 82.55 分、混料版 Sol 69.85 分，相差 12.70 分；完整清空回合从 7/8 降至 6/8，且六个完成回合整体较慢。混料版本轮提供了额外的节拍与多件恢复压力，尚未体现出可量化的错投风险。两版本采用各自独立开发的策略，这不是对同一策略仅开关分类要求的受控消融，不能将分差全部解释为分类本身增加的难度。

每模型每版本仅一轮有效开发提交；八个隐藏回合描述该冻结策略的表现，不是八次独立 agent 开发重试。当前结果支持保留两版进行后续扩展，但不能据一次开发宣布稳定的模型排名。此前被接口并发限制打断的原题 Luna 轮次单独保留，不进入上述四组工程分。正式四组均有冻结记录、完整八回合报告，无当前轮次异常；32 段视频的帧数已与原生 ticks 核对，见 `final_audit.json`。
