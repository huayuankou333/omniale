## 原题：已确认的实现

冻结策略 SHA-256：`98ffcb762f3aa175321c4ffdbf670b32f8bf7b822346522f53d2c1a9acde1962`。

代码使用有效 `arm_grip` 控制点、六维位置与姿态反馈、阻尼 Jacobian 逆和关节限幅。顶视深度投影生成高度候选，腕部 F/T 用于接触判断与负载估计。单件进入正常搬运；双件进入工位再抓取分离分支；估计三件及以上时送回料箱。代码包含扫描遮挡规避、失败点更新和重试。未发现读取实时物体真值、隐藏种子或导入 harness 的逻辑。

首个原生回放已核查为 90.2 s、902 帧、10 fps。`frames/deepseek-original-ep0.png` 对应 0、30、60、90 s 的帧，能观察到抓取和搬运。图中料箱零件减少本身不等于有效清出或满分，必须与原生清出、安全处罚和完整清空记录核对。

## 混料版：已确认的实现

冻结策略 SHA-256：`ebdd2faed32015bd8aef796da232ca6db8f6da30f9accfce8d7abb38b8a89459`。

代码以 `arm_magnet` 刚体和公开磁头几何构造运动学目标，用非线性最小二乘求位置/朝向 IK。最终目标朝向矩阵是合法旋转。顶视 RGB 与中值滤波深度用于分割、选点和避开失败点；提升后，世界坐标 F/T 增量的范数与 2.05、3.02、3.72 N 三个原型匹配，并使用重力方向和横向力门限。力矩与力增量的作用线估计抓取偏移，再修正工位中心投放坐标。最终代码使用力觉偏移估计，没有把开发中讨论过的腕部视觉方案写成实际采用的方法。

该实现尝试渐进提升、过力中止和无候选时停车刷新视野。没有发现读取实时类别或物体位姿、隐藏种子、其他模型产物或导入 harness 的逻辑。按质量辨识符合本版规则，因为长度变化同时按规则改变质量。

## 冻结方法的合成探针

`../diagnose_dashscope_mixed.py` 从冻结文件的 AST 提取 `plan_abort`、`execute`、`hold_cmd` 和 `classify` 四个方法，以合成状态及传感器样本执行。原文件保持原样，没有运行或改变隐藏场景；[原始记录](dashscope-mixed-probes.json) 明确标为 `engineering_score=false`。

1. **过力中止状态被覆盖。** 提升分支在力增量大于 420 N 时调用 `plan_abort()`，紧接着返回 `execute()`。后者会将状态改为 `settle`，并返回原轨迹中的磁铁命令。探针对轨迹指针为 0 和 1 的两种情况都得到 `abort → settle`、磁铁命令 128。因此这条调用路径没有进入预期的 `abort` 状态处理与去磁释放。是否实际解释损伤，必须结合对应回合的事件或轨迹，不能仅凭代码推定。

2. **两件短件与单件长件的重量存在接收区间重叠。** 合成单件载荷 2.05、3.02、3.72 N 分别正确返回三类；两件短件的合重 4.10 N 仍满足有效区间与方向门限，距长件原型仅 0.38 N，小于 0.60 N 容差，结果返回长件类别 2。该探针证明分类阈值存在多件歧义，尚不能证明隐藏回合实际出现了该组合或因此产生多少错投。

模型最后陈述中的公开短测和“无处罚”仅是开发诊断，不能覆盖原生隐藏验收事实。误差归因需先检查每回合有效清出、完整清空、吞吐、安全处罚、错投及计算预算，再将已发生的现象与冻结代码和回放对应。两版独立开发，本轮不是只改变分拣要求的受控消融；每版仅一轮有效 agent 开发，八个隐藏回合不等于八次独立开发重试。

本轮混料版实际记录零损伤，不能把过力中止探针直接写成已发生的损伤原因。两次错投也不足以证明一定由“两短件被当成长件”触发；该阈值歧义仍属于冻结实现的已确认风险机制。
