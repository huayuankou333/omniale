本文件分析 `dexjoco_20261105T133947Z` 中两模型的 `rand_obj/seed0/episode_00_failure`，证据为三路原版录像、冻结策略源码和开发工具轨迹。它不是对尚未完成的 600 回合做总体结论。

| 模型 | 首个正式回合中可见的行为 | 失败位置与证据范围 |
|---|---|---|
| gpt-6-luna | 左手接近并保持托盘，右手多次尝试夹取/重抓销；到 1500 步仍未形成稳定搬运、对齐和插入序列 | 抽帧显示销与手的相对姿态持续变化，末段销仍接近桌面。结合源码中以手指关节闭合近似“已抓住”的判断，可推断抓取确认与恢复不足；仅凭视频不能证明每次接触力和物体真值 |

## 策略与开发差异

Luna 的冻结策略主要使用 overview 图像的颜色分割、固定相机模型反投影、经验式手姿和观测驱动控制。表高变化与抓取误判会影响后续目标；overview 相机随机化时，固定标定也是潜在的泛化风险，尚不能在 `rand_full` 正式测试前断言最终表现。

6.1 Sol 的策略增加了三视图几何/轮廓拟合、静态手模型运动学、持物位姿校正、分阶段对齐及孔附近搜索。它的视觉估计更耗时；首批正式请求中延迟分布具有长尾，异步 evaluator 会按原规则继续推进物理并处理动作时间戳。具体统计随 `progress.json` 更新。

Luna 在 7200 秒预算到期后被监督器停止，保留当时有效的可导入策略，退出码 137 是该预算停止的记录。6.1 Sol 在截止前主动完成提交。两者都没有经主控修改解题代码。Luna 没有正常 turn.completed，因此其完整 token 结算数据缺失，不能当成零 token；6.1 Sol 的 CLI usage 保存在 status.json。

## 实验限制

- 原论文 VLA 使用示范训练，并按随机化条件分别训练；这里是一次 coding-agent 策略开发实验，不能声称训练条件相同。
- 本轮开发工具的 `rand_full` camera_mapping 错误使该条件未完成开发验证；正式 evaluator 读取正确的上游 YAML，不受此映射错误影响。本轮应解释为主要经 `rand_obj` 开发的策略在两条件上的正式测试。
- 更早的首轮开发使用多线程 HTTP 导致 OSMesa 图像全黑，已整体作废，不计入本轮成绩。
- 当前是 CPU + OSMesa，异步执行的真实时间与论文硬件不同；只能直接比较本实验内相同硬件与预算下的两个 agent。
- 完整计划为每模型两条件各 3 seeds × 50 回合。尚未完成时只报告已落盘回合，不给出冒充完整协议的均值、标准差或论文排名。
