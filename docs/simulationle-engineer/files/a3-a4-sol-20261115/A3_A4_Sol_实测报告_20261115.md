## 章节解析器的纠错与同一冻结提交复评

v2文档检查错误地只接受 `## Architecture` 等二级标题，但题面和JSON契约只要求存在 Architecture、Parameters、Validation、Limitations 四节。A3交付使用了完整的一级标题，被误判为非法交付，电气验收因此没有启动。这一原始0分记录作废，不属于模型能力失败。

v3只将标题级别识别改为1至6级，仍检查相同四个章节名称；对六种合法级别、缺章节及正文提及反例做了检查。两题统一使用这一修复，保持原始冻结电路、报告、原题脚本、夹具、阈值与评分公式。没有重跑模型，也没有增加开发预算。v2原始结果和封存清单、v3修复声明和封存清单全部保留，最终分数以 `result_docfix_v3.json` 为准。

## 已作废的基础设施尝试

首次 A3/A4 会话的策略检查使用逐次启动的 Docker 容器，出现检查已通过但启动/退出阶段超时的情况，导致模型工具失败。两个会话均被中止、保留现场并记为 null；其候选没有进入正式测试，也没有继承给新会话。修复后使用常驻仿真容器、Linux宿主执行相同的纯静态检查器，并将 Docker 通信故障与原生求解超时分开。镜像系统默认请求8个线程，修复版用 `OMP_THREAD_LIMIT=1` 避免在2核额度下争用；电路、原题脚本、平台、阈值及评分不变。

## 结果的适用范围

修复后的执行器通过真实网关、隔离、预算和测量反例检查。两份原题参考在原始电路验收中分别通过8/8和15/15；A4平台的−8目标符号与比例还由独立理想控制检查。此前交付的题目契约及原题脚本保持原始哈希。

两道改编题尚未具备“合法器件参考解通过原题及全部新增矩阵”的完整可行性证明，因此本轮是当前草案契约下的 Sol 实测。不能仅凭 Sol 失败，就断言 case 已完成可行性与难度校准。参考回归通过也不等于新增全矩阵存在已验证满分解。

详细分组、测量值、失败条件、调用记录和源文件哈希均已保存。大型原始波形留在服务器各次 `final_evaluation_docfix_v3/application/`，证据包保留解析后的逐任务测量与运行日志。
