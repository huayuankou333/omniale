# Recreate ngspice 36

You have the released ngspice executable at `/usr/local/bin/ngspice`, official version-matched user documentation in `/docs/manual/`, and a few input examples in `/docs/public/examples/`. Use the executable as a black-box oracle and read the documentation to discover behavior. The container is offline.

Create an independent implementation of the documented public command-line behavior of this build. A caller should be able to replace ngspice with your executable, without changing the CLI options, native SPICE input decks, control language or output formats. Reproduce simulation capabilities, file and stream behavior, and diagnostics. You may use the generic compiler, standard libraries, NumPy, SciPy, BLAS and LAPACK installed in the environment. You can select your own language and code architecture.

Do not access original program source, reverse engineer or disassemble executable artifacts, copy program binaries, use ngspice or another existing SPICE simulator as a backend, include libngspice, or use prerecorded solutions. You can use the reference normally through its documented interfaces, including CLI commands and input files. Public examples are useful for exploration. Write a general implementation that works for unseen netlists, parameters and combinations of functions.

Submit complete source in `/submission`, including a POSIX `compile.sh`. The evaluation invokes `bash compile.sh` from a fresh copy of the source, with `OUTPUT_DIR=/out`. Your script must place the independent executable at `/out/ngspice` and any needed runtime files within `/out`. It must work without network, the reference binary, or the hidden tests. Generic preinstalled numerical libraries remain available. The executable is invoked directly, with the same arguments, current working directory, standard input, and output-file conventions as ngspice. It should read relative paths from the working directory and support ordinary netlists and control scripts.

Evaluation uses native command-line tests on unseen input files, comparison against the locked reference, and format-aware numeric comparison. Real and complex vectors, plot types and required file outputs are checked. Transient results may use independent integration steps if they satisfy the waveform and sampling requirements. Failures must exhibit the corresponding observable diagnostics and exit behavior. Volatile banners, timestamps and resource use are not scored. Every implemented and tested group is reported; all required tests must pass to resolve the task.
