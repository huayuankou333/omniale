# Recreate RAYX 1.1.0

You have the released Linux RAYX 1.1.0 command-line executable at `/opt/rayx/bin/rayx`, official documentation and public example inputs in `/docs/public/`, and the material-data tables distributed with the release at `/opt/rayx/share/RAYX/Data`. The container is offline. The release's `--help` output takes precedence over older documentation when CLI options differ.

Create an independent implementation of the public CPU/headless command-line behavior of this build. A caller should be able to replace RAYX with your executable while retaining the CLI options, RML XML beamline files, input data tables, and native CSV and HDF5 outputs. Reproduce ray generation, propagation through ordinary research-optics beamlines, material interactions, event recording, and file/diagnostic behavior. Support a general implementation for diverse sources, optical components, configurations, seeds, and combinations of features.

You may choose your language and use the generic compilers, HDF5, NumPy, SciPy, h5py, BLAS and LAPACK available in the environment. You may copy the distributed material-data tables as static scientific input data with the appropriate attribution. Use the reference solely through its documented interface. Do not access the reference implementation source, disassemble reference binaries, copy reference code or executable/library artifacts, use RAYX or another optical simulator as a backend, or hardcode prerecorded outputs. Public inputs are for exploration.

Submit complete source in `/submission`, including a POSIX `compile.sh`. Evaluation invokes `bash compile.sh` in a fresh clean copy with `OUTPUT_DIR=/out`. Your script must produce `/out/rayx` and place required runtime files within `/out`. The build and execution are offline, in a generic image without the reference executable, reference library, public examples, or the hidden grading suite. The resulting executable is invoked directly with the same CLI, working directory and input files as the reference.

The evaluation runs native CLI tests on unseen RML files and compares generated files, data structures and numerical values against the version-locked reference. It checks event order, ray and object identifiers, seeded behavior, numeric attributes, HDF5 metadata and output-file conventions, as well as stable CLI and diagnostic contracts. Floating-point fields have numeric tolerances. Volatile elapsed times, platform-specific CPU names and build timestamps are excluded. GPU execution, the graphical UI, and interactive plotting are outside the v0.1 CPU/headless contract. All qualified tests must pass to resolve the task.
