01 / THE MANIPULATION TASK

先抓稳，再把两个持物坐标系对齐。

在固定机器人上开发策略

左手抓住蓝色托盘，右手抓住黄色销，将销插入孔中。两只 16 自由度灵巧手由双 Panda 机械臂承载；Agent 自主开发可执行控制器，以三路视觉和本体状态闭环决策。

SUCCESS CRITERION

触发原版装配成功

销与孔底指定几何体连续接触至少 30 个控制步；最多 1500 步，成功率二元计分。

约束与现行开发预算

  • 固定原版机器人、资产、物理参数、随机化与成功函数。
  • 正式策略不能读取物体真值位姿或 MuJoCo 内部状态。
  • 现行统一协议：每模型最多 2 小时（7200 秒），允许提前提交，开发期 reset 与仿真试验次数不限。
  • 开发使用独立种子，提交冻结后进入原版异步评测。
  • 不为抓取、抬升或接近孔等中间动作人工加分。
TWO RANDOMIZATION CONDITIONS

rand_obj 随机物体位置、朝向和桌高；rand_full 再随机相机、光照及桌面纹理。本轮仅完成前者的部分测试。

05 / FAILURE ANALYSIS

失败发生在不同的操作阶段。

查看分析依据 ↗

下面的行为分析针对两模型的第一个完整失败回合，结合三路录像与冻结源码；它不是对所有失败回合做逐例归因。观察与机制推断分别陈述。

01Luna · 抓取确认

手指闭合了，
物体未必已被稳定抓住。

录像观察：左手接近并保持托盘；右手多次尝试夹取和重抓销，到 1500 步未形成稳定搬运、对齐与插入序列。

源码线索：策略用手指关节闭合近似判断“已抓住”。据此推测抓取确认及失败恢复不足；录像不能单独证明每次接触力或物体真值。

02Sol · 持物对齐

能把销送到孔附近，
仍未完成持续插入接触。

录像观察：右手抓起、抬升并旋转销，两臂靠近托盘；后段在孔附近操作，没有触发原版成功条件。

解释范围：表现指向抓取后的姿态、位置对齐或阶段收敛问题。未记录每次推理的内部 phase，不能确定卡在某个精确代码分支。

03异步控制 · 运行条件

感知更复杂，
也需要考虑动作何时生效。

Luna 使用颜色分割、固定相机几何与经验手姿。Sol 增加多视图拟合、手模型与孔附近搜索，其推理耗时有长尾。

评测影响：原异步循环会在等待新动作时继续推进物理。CPU/OSMesa 与论文硬件时序不同；未做消融，不能把失败归因于时延。

04实验限制 · 结论边界

保留任务难度，
也记录开发环境的问题。

本轮开发工具的 rand_full 相机映射有误，该条件未完成开发验证；正式评测器映射正确，但本轮在进入 rand_full 前已被用户停止。

记录边界：更早出现黑图的运行已整体作废。当前两模型提交保持原样；444 / 826 个冻结文件通过 SHA256 校验，未进行人工解题修改。

后续如何判断这个 case 的区分度

本轮支持“在当前开发条件下尚未观察到装配成功”的结论。要进一步比较 agent，应先修正开发接口，固定相同的评测回合量，再重复独立开发；保留二元任务成功率，同时用录像诊断抓取、持物估计、对齐和插入阶段。中间阶段诊断不替代原版分数。

开发：Codex CLI 0.118.0，high reasoning，模型 ID 为 gpt-6-luna / gpt-6.1-sol。现行统一协议为每模型最多 7200 秒，允许提前提交，开发期 reset 与仿真试验次数不限；提交冻结后独立验收。本页历史成绩对应的运行从一开始即采用 7200 秒开发预算，同时实际执行了 12 次 reset 上限，尚未按现行不限次数协议重测。Luna 到时停止，进程退出确认约多 10.7 秒，属停止开销；Sol 用时约 7124.2 秒，主动提交。

Sol CLI 结算为 14,552,927 输入 token（含 13,997,568 缓存输入）、100,362 输出 token。Luna 未正常结束 turn，其完整用量缺失，不记为零。网关模型 ID 已核对，服务端权重身份未经独立审计。

正式仿真：4 CPU / 16 GiB；策略：1 CPU / 4 GiB；MuJoCo 3.4.0、NumPy 1.26.4、OSMesa。原版 30 步动作块、0.8 重规划比、时间戳对齐、重叠融合、1500 步上限与持续接触成功判据保留。CPU 软件渲染会改变异步时间关系。

截至 2026-11-06 12:15:09（UTC+8）两模型共 47 个完整评测回合。停止时 Luna 第 25 回合、Sol 第 24 回合未完成，未计分；rand_full 未执行。完整录像与原生执行归档保存在项目服务器，本页仅打包两模型首个完整回合的三路录像。
