# 交付技术规范

本文件与题面配套。v0.1正式输入尚未冻结，媒体参数须在 `INPUT-MANIFEST.json` 中填写实际值后冻结；不以237秒标称时长代替实测。

## 成片与音频

- `final/ad_version.mp4`：H.264视频、AAC音频，保留原片显示尺寸、帧率、画幅、镜头和画面次序，不叠加字幕、水印或装饰。允许必要的编码转换。成片时长与输入实测时长差不超过一帧或0.05秒中的较大值。
- `audio/ad_stem.wav`：48kHz、24-bit PCM、单声道。与原片同长，起点0秒；新增AD全在其中，无原声、音乐或提示音。末尾可以是静音。
- `audio/mix.wav`：48kHz、24-bit PCM、双声道，与原片同长。与MP4内音频在相同时间位置一致，编码差异除外。原片为单声道时允许居中输出双声道。
- 原对白、环境声和音乐不得删去、移动、替换、加速、变调或通过重度分离处理破坏。允许增益、合理EQ及口述期间的音量闪避；以原声可理解和节目保真为准，不强制某个闪避数值。
- 无削波、明显截字、爆音和突兀音量跳变。混音母带真峰值不高于-1dBTP。峰值合规本身不授予内容分；响度不统一到某个值不自动判错。
- 每句AD有独立可编辑的语音片段，或在同一完整声轨中有明确的片段边界。口述与原声必须为不同轨道。

## AD脚本

`script/ad_script.json` 顶层含 `version`、`language`、`source_sha256`、`duration_seconds`、`segments`。

每段含：

|字段|含义|
|---|---|
|`id`|唯一标识，例如 `ad-001`|
|`start`、`end`|相对原片0秒的实际新增声音起止，单位秒；首尾纯静音不计，末尾自然发声尾部计入|
|`text`|成片实际说出的英语文稿，允许常规标点归一差异|
|`audio_file`|相对于提交根目录的独立句子WAV路径|
|`track`|固定为 `AD`|

片段按 `start` 递增，时间范围在原片以内，彼此不重叠。不要填写理想时长、预计时长或仅编辑器选择区域。JSON真实起止与音轨审计差异超过0.10秒时须修正。实际声音与文稿冲突时，以声音为准。

SRT只含新增AD文字，不能用原对白字幕填充。时间与JSON一致至毫秒；它是编辑和审核材料，不要求烧入画面。

`delivery.json` 须符合 `schemas/delivery.schema.json`，记录上述文件、工程、复核页和工具。完整交付还需 `CREDITS.txt`。文档不要带入机器密钥、个人缓存或不必要的原始日志。

## REAPER工程与复核页

- `project/session.rpp` 使用相对路径引用打包媒体；没有用户目录或服务器绝对路径依赖，没有缺失插件或缺失媒体。
- 至少包含 `ORIGINAL`、`AD` 两类轨道。保留实际片段位置、增益及混音所用自动化；不接受只有一条最终混音的空壳工程。
- 如生成了多句语音，按句命名并放在 `audio/segments/`。可以在本地编辑器中直接移动、更换或重渲染。
- `review/index.html` 能播放原片及交付版、按AD句定位，并有明确的版本标签。以 `python -m http.server` 启动后可使用，不连接外部服务。
- `README.md` 写清如何打开工程、播放对照、渲染混音和封装MP4；声明实际用到的软件版本、TTS及音色。无需把通用大型权重重复打包进最终交付，但须给出来源、版本和校验值。

## 工程门槛

必须有可播放成片、与成片相符的口述干声、真实时间脚本、可编辑且不缺媒体的REAPER工程。检查引用文件、时长、声轨和内容保真。技术门槛没有单独分数；轻微的修复性问题先记录并要求同规则修复，不能用组织者工具故障压低内容分。

若最终未交付成片、没有可听AD、改变原节目结构，或使用隐藏专业参考作为模型输入，本轮不具备正式内容评测资格；保留失败类型，不虚构听评总分。明确没有AD的有效原片交回基线按题面记0分。
