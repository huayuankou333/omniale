# 为一支纪实短片制作原时长口述影像版

> 构题草案 v0.1，2026-11-24。正式输入、工具和评分校准尚未完成，本版本不能直接启动模型测试。正式开测前，组织者须提供有效的 `input/source.mp4`、完整清单、可用的本地播音工具及冻结版本号。

你是一名负责无障碍版本交付的音视频后期编辑。客户已有一支英语纪实短片，希望视障观众在听清原有旁白、现场对白和重要声音的同时，知道画面中发生了哪些原声没有交代的事情。

请根据原始音视频，独立撰写、配音并混入**英语口述影像（Audio Description，AD）**，交付一支可以直接播放的完整版本，以及后续编辑可以接手修改的工程。

客户需要沿用原片的固定时长与画面。你必须选择值得补充的信息，安排插入口述的时机，让实际语音在可用的时间内自然播完。

## 输入

正式输入只包含：

- `input/source.mp4`：约4分钟的原始有声短片，含英语旁白、现场对白及其他声音。它是你需要处理的完整节目，不是无声片，也不是已经加入AD的版本。
- `INPUT-MANIFEST.json`：文件校验和、实际时长、分辨率、帧率、声道等技术信息；以开测时通过预检的版本为准。
- `tooling/`：经组织者验证可用的离线英语TTS入口、固定音色、使用说明与软件/模型许可。你可以使用该入口，也可使用环境中其他可用且来源合规的通用播音工具。
- 本题面、`SCORING.zh-CN.md`、`DELIVERY-SPEC.md`、交付JSON Schema与环境说明。

不提供专业口述参考、对白转写、镜头摘要、人物关系表、重要事件表或可用静默时间窗。允许用通用工具自行提取这些信息。你不需要寻找原视频、专业AD稿或该节目的既有无障碍版本。

## 工作要求

### 1. 确定哪些信息值得补充

完整观看并试听原片。让听众能理解人物正在做什么、场景如何变化、重要动作的结果，以及理解节目所必需的可见文字。

优先补充原声没有清楚表达的信息。原旁白已经解释的事情不必再说一遍；普通环境声、表情和细节应按其理解价值取舍。不要仅凭声音猜测画面，也不要把自己的解释、人物心理或不确定身份当成事实。

允许采用稳定且清楚的称呼，例如“the vlogger”“his companion”。若原片没有可确认的姓名，不要求猜出姓名。可读性不足的文字不要求逐字复述；不要为念清不确定内容而编造。

### 2. 把口述安排到合适的时机

使用原片自然存在的间隙，实际试听口述与原声的结合。对白暂时停顿不一定等于可以说话：对理解事件重要的现场声和声音提示也需要留出空间。

信息须在观众需要它时出现。不要提前揭露尚未发生的动作；也不要在画面和话题已明显转移后才解释。允许合并、拆开或简化句子，不要求固定句数、参考稿措辞或精确复制某个时间点。

对已生成的语音检查真实起止，不能只用字数估算播放长度。不要用持续高速播报填满所有空白，也不要在对白上方靠提高音量硬插口述。

### 3. 保留节目，完成声音后期

- 完整保留画面、镜头顺序、原声时间位置和原片时长；不删片段、不加暂停帧、不插黑场、不改变播放速度。
- 保留原片全部声音。允许在新增口述下对原声作适度音量闪避与平滑淡入淡出；原对白和需要保留的声音必须仍可理解。
- 新增旁白使用一个稳定、清楚的英语音色。不得克隆原片人物声音。声音风格自然、中性、适合节目；不以模仿某个特定声线评分。
- 使用 **REAPER** 整理原声和AD，保留可编辑的轨道、片段及必要音量自动化；输出混音后完成视频交付。可另用Shotcut或FFmpeg封装成片。
- 仅完成剪辑脚本、字幕或配音文稿不算完成委托；评测会播放实际成片。

## 最终交付

保存到 `/workspace/submission/`，具体技术要求和字段见 `DELIVERY-SPEC.md`：

1. `final/ad_version.mp4`：原画面、原时长、原声音与新增口述的完整成片。
2. `audio/ad_stem.wav`：与原片同长、从0秒开始对齐的独立口述干声轨，无口述处为静音。
3. `audio/mix.wav`：与成片一致的完整混音母带。
4. `script/ad_script.json` 与 `script/ad_script.srt`：实际播报文字及每段真实声音起止，JSON符合 `schemas/ad-script.schema.json`。
5. `project/session.rpp` 与其引用的所有必要媒体：可在新路径中打开和重新渲染的REAPER工程，原声与新增口述分轨。
6. `review/index.html`：完全离线可用的原片/成片对照试听页，包含可点击的AD句表与同步定位。页面以本地HTTP服务打开，不依赖外部CDN。
7. `README.md`、`delivery.json`、`CREDITS.txt`：打开/重渲染步骤、实际工具与音色来源、校验信息、来源署名。不要写入密钥。

可以补充不超过800个中文字的 `editor-notes.md`，说明主要取舍和已知不足。解释文字不能代替实际成片，也不因解释得好而加内容分。

## 工具与预算

全部制作和评测在服务器Docker进行。正式环境须通过 `ENVIRONMENT.json` 的开测检查：REAPER、FFmpeg、FFprobe、Python、JSON Schema校验器、音频处理依赖及可正常发声的离线英语TTS。Shotcut为可选封装工具。

计划资源为8 CPU、16GiB内存、30GiB工作空间，不承诺GPU。有效工作时间120分钟，最多140次成功候选模型调用，累计输出131072 tokens、单次最多8192 tokens。公开网络请求最多80次、下载最多2GiB，失败请求和重定向计入；组织者预置输入及TTS不占额度。

允许获取通用依赖、工具文档和通用模型。不得查询本片对应的专业AD、MTG-AD参考标注、他人本题答案或隐藏评分资料。运行容器不挂载组织者的参考目录。输入文件和工具未通过开测检查时不启动计时，组织者环境故障不算模型内容错误。

## 评分

工程和完整交付作门槛，无工程基础分。100分均评实际口述影像效果：

|维度|分值|
|---|---:|
|重要视觉信息覆盖与准确性|45|
|插入时机、对白与关键声音保护|30|
|信息精炼与原声互补|15|
|实际播报与混音质量|10|

评分使用原片及组织者保留的专业AD作为证据，接受合理改写、替代称呼和排布。新增但正确、有用的信息不会因为专业参考未写而被判错；专业参考也不是一份必须逐字复刻的脚本。无新增AD时内容总分为0；仅填入文稿而没有实际播出也没有内容分。

高分成片应让听众获得关键画面信息，减少对“看见了什么”的猜测，同时保持原节目的声音、节奏和理解连贯性。详细计算规则见 `SCORING.zh-CN.md`。
